# 当前版本综合 Benchmark — 2026-11-17

本轮重新构建并测量当前版本，结论是：常用词和回归集内的整句输入延迟较低；
超长全拼的音节切分递归存在可复现的计算长尾，应优先处理。
这是当前版本的绝对性能基线，没有用历史优化百分比代替本次测量。

## 环境与统计口径

- 源码基线：`49b69323cd2b89e2cc436843fbd4b8c914b8664c`。本次新增评测工具；
  输入引擎、候选排序、搜索预算和词库均未修改。
- AMD Ryzen 9 7940HX，32 逻辑 CPU，约 14 GiB 内存，Fedora 45，Linux 7.3.3，
  Rust 1.99.1，IBus 1.5.35；release 默认优化及 bundled-fonts。
- CPU governor 为 `powersave`，动态频率、未绑核；桌面其他进程仍在运行。
  各性能实验串行运行，编译和测试在计时实验之外进行。结果代表本机工作负载下的表现。
- 完整本地词库 141,873,016 字节；镜像、二进制、源码哈希保留在 JSON 中。
  公开演示词库不能用于复现这些完整词库数值。
- 每组 7 个独立进程；核心候选、质量和 IBus 实验另有未计入的预热运行。
  报告的 P50/P95/P99 均是「各轮对应分位数的中位数」，不是混合全部事件后的分位数。
  原始 JSON 同时保留各轮值及跨轮最小/最大值。
- 引擎探针沿用 `sorted[N * 95 / 100]` 等索引；IBus 探针沿用 nearest-rank。
  少样本压力组的 P95 可能等于该轮最大值。
- 不删除离群点；文中“全样本最大值”取七轮中的绝对最大值。
  墙钟时间包含调度等待；独立诊断增加线程 CPU 时间，用于归因。
- 所有 XDG 设置、导入词库、学习记录和 D-Bus 实例均隔离。
  不更改桌面输入源、不读取个人学习记录、不清空全局页缓存。

## 候选计算与质量

固定语料为 200 个常用词、25 句的全拼/简拼/混合输入共 75 例。
每轮候选性能测试包含 1,202 次短词按键、1,529 次整句按键、1,375 次编辑、
275 次向前翻页、2,731 次缓存重放按键及 200 次完整 `suggest` 查询。

- 短词按键：P50 **0.051 ms**，P95 **0.250 ms**，各轮 P95 范围 0.242–0.255 ms。
- 整句按键：P50 **0.248 ms**，P95 **3.097 ms**，各轮 P95 范围 3.085–3.150 ms；
  全样本最大值 **4.541 ms**。
- 编辑：P95 **1.546 ms**；向前翻页 P95 **0.010 ms**。
- 缓存重放按键：P95 **0.025 ms**；完整短词候选枚举 P95 **0.574 ms**。
- 七轮常用词首选均为 **200/200**；整句首选均为 **74/75**。
  未命中的是 `xwsdzmkj`，期望“下午三点在门口见”，首选为“下午三点在门口就”。
  这些是人工回归集结果，不代表自然语言总体准确率。
- 三轮候选轨迹各 7,564 条，其中 7,563 条完全稳定。
  第 4,435 条 `xianqchifan` 的完整 `suggest` 列表存在轮间变体。
  未将这一条当作完全确定的输出，也未因此删除性能样本。

## 首屏与预加载

每轮覆盖 200 个词、1,202 次首次输入按键及 1,202 次重放按键。

- 零键间隔：首字母 P95 **0.078 ms**，所有首屏按键 P95 **0.268 ms**，重放 P95 **0.019 ms**。
- 键间隔 2 ms：首字母 P95 **0.017 ms**，所有首屏按键 P95 **0.016 ms**，重放 P95 **0.013 ms**。
- 两种模式七轮首选均为 200/200。2 ms 是探针在计时区间外留出的预加载机会，
  不是从物理键盘到显示器的延迟；该组仍观察到 **34.899 ms** 的单次最大停顿。

## 私有 IBus 链路

每轮包含 6,031 次请求，覆盖输入、选词、双向翻页、编辑、忽略事件及提交。
分别运行直连引擎与真实私有 `ibus-daemon` 路由，两种模式均做预热及七轮独立测量。
两次独立 UI/提交/回复轨迹在各自模式内均 **6,031/6,031 完全一致**。

- 直连：短词按键 P95 **0.793 ms**；整句 P95 **3.714 ms**、P99 **4.325 ms**；提交 P95 **0.521 ms**。
- 经真实 IBus 路由：短词 P50 **0.642 ms**、P95 **1.021 ms**、P99 **1.503 ms**；
  整句 P50 **0.921 ms**、P95 **3.895 ms**、P99 **4.513 ms**。
- 路由模式：编辑 P95 **0.695 ms**，翻页 **0.771 ms**，选词 **0.720 ms**，提交 **0.690 ms**。
- 路由整句各轮 P95 为 3.829–3.974 ms，全样本最大值 **6.061 ms**。
  路由短词全样本最大值 **3.807 ms**。
- 每轮路由接收 9,401 个信号、6,683,896 字节 D-Bus 消息，七轮一致。
  字节数包含 D-Bus 消息头，不包含认证及 socket framing。
- 默认关闭日志；另行开启 handler 诊断，最后一个完整窗口中 handle P95 为 **3.697 ms**，
  present P95 为 **0.113 ms**。这是归因数据，不是两者独立分位数可相加的分解。
- 信号去重断言通过；100 次引擎创建/销毁后总共 **10 个 fd**，已销毁对象均返回 UnknownObject。

IBus 时间从客户端发送请求到读取回复，包含此前 UI 信号的解码；词库初始化在计时区间之外。
它不覆盖物理键盘事件、GTK/Qt 文本插入、GNOME 合成或帧呈现。
候选探针和 IBus 探针的编辑/缓存状态也有差异，不直接相减估计“纯传输开销”。

## 加载与导入文件数量

- 完整词库热页缓存加载中位数 **38.944 ms**；私有磁盘副本冷页缓存加载 **146.484 ms**。
  冷测只对私有副本执行 `POSIX_FADV_DONTNEED`，目录位于 NVMe 上的 Btrfs；
  七轮都观察到了 major fault，中位数 35。它不是硬件缓存全部清空后的启动时间。
- 加载计时覆盖 `Lexicon::load`，不等于进程启动到桌面可输入的总时间。
- 导入目录分别放置 0 / 100 / 1,000 个 TSV，每个仅一条 `ni → 你`。
  每轮先预热 8 次，然后测量 1,000 次 `n` 开始组合并清空：
  P95 分别为 **0.003 / 0.115 / 0.952 ms**。
- 文件数场景暴露组合边界/导入候选的扩展成本；它不代表每份十万词的大词库解析吞吐量。
  `Session` 构造和首次导入解析未包含在这组按键计时里。

## 独立引擎进程内存

在计时实验结束后，另起七个独立引擎，完成输入语料后读取 `/proc` 快照；
再用七个新进程单独完成 100 次创建/销毁循环后采样。没有把探针进程的内存当成引擎内存。

- 跑完语料后：RSS 中位数 **146.629 MiB**，文件驻留 **142.742 MiB**，
  匿名驻留 **3.859 MiB**，PSS **144.078 MiB**；3 个线程，13 个 fd。
- 100 次创建/销毁后：RSS 中位数 **143.715 MiB**，匿名驻留 **1.207 MiB**；
  3 个线程，七轮均为 **10 个 fd**。
- 文件驻留包括只读词库映射和可执行文件/共享库页；这些值不能全部解释为私有堆。
  PSS 依赖当时同一文件页的共享情况，匿名驻留也不是分配器的完整堆统计。
- 这里是操作结束时的快照及进程高水位记录，不是长期会话的泄漏证明或闲置功耗测试。

## 极端输入与优先级

每轮对四个固定模式分别测试 8、16、32、64、128、256 个 ASCII 字母，
共 24 组、2,016 次按键；使用固定默认模糊音设置，不启动后台预加载。
另运行七轮逐键墙钟/线程 CPU 诊断，原始 256 键记录全部保留。

1. **优先处理超长全拼音节切分路径。** 重复 `jintianwomenyiqiqugongyuan` 时，
   第 177 / 203 / 229 / 255 键的墙钟中位数分别为
   **5.380 / 21.124 / 81.155 / 324.685 ms**；对应 CPU 时间几乎相同。
   第 255 键 CPU 中位数 **322.225 ms**，七轮墙钟范围 318.661–336.237 ms。
   常规压力组还记录到 **374.062 ms** 的全样本最大值。
   单独用 Callgrind 只采集第 255 键，共 **3,377,397,683 条用户态指令**；
   `segmentations::walk` 入口覆盖约 **99.98%**，其递归实现自身占 **60.75%**。
   这是音节切分的计算问题。源码以 48 条成功输出为停止条件，没有总访问次数预算；
   该条件不能限制无成功输出分支的遍历量。这一代码观察与剖析结果一致。
   建议评估失败后缀记忆化或总工作预算，并用参考算法验证候选语义。
2. **高歧义长简拼。** 重复 `sh` 的 128 字母组 P95 **15.607 ms**；
   重复长简拼模式的 128 字母组 P95 **24.014 ms**。
   初始压力组包含最高数百毫秒的墙钟离群值；CPU 诊断显示部分停顿有明显调度等待，
   不把所有墙钟尾部都归因于搜索算法。
3. **导入词库扩展成本。** 单记录文件从 0 增至 1,000 时，组合按键 P95 增至约 0.95 ms；
   可进一步评估导入候选索引与文件合并。
4. **候选稳定性及质量。** 保留已观察到的完整枚举顺序变体，并修复回归语料中的单个简拼误选。

整句 beam search 原本在输入超过 128 字母后停止，但音节切分在该阶段之前运行。
因此超过 128 字母的某些组耗时下降伴随搜索回退，不能据此推断长输入扩展性良好。

## 复现与产物

```sh
cargo build --locked --offline --release --examples --bin waypinyin
python3 scripts/benchmark.py --image /absolute/path/to/full/lexicon.bin \
  --output build/benchmark-current --runs 7
python3 scripts/benchmark_memory.py --engine target/release/waypinyin \
  --probe target/release/examples/ibus_latency \
  --image /absolute/path/to/full/lexicon.bin \
  --output build/benchmark-current/memory.json --runs 7
```

单独运行逐键 CPU 诊断时，给 `benchmark.py` 增加 `--diagnostics-only`，并使用另一个输出目录。
全套需要 Linux `/proc`、`/usr/bin/time`、`dbus-daemon`、`ibus-daemon`，以及完整本地词库。
不需要修改或重启桌面 IBus。

热点指令剖析可用以下命令复现；也应在隔离的 XDG 目录下执行：

```sh
raw=$(python3 -c 'print(("jintianwomenyiqiqugongyuan" * 11)[:255])')
WAYPINYIN_LEXICON=/absolute/path/to/full/lexicon.bin \
  valgrind --tool=callgrind --collect-atstart=no \
  --toggle-collect=waypinyin_profile_key \
  --callgrind-out-file=build/full-pinyin-255.callgrind \
  target/release/examples/search_hotspot "$raw"
callgrind_annotate --inclusive=no build/full-pinyin-255.callgrind
```

指令数不等于 CPU 周期或原生运行时间；递归函数的 inclusive 计数可能重复计入递归层，
因此不使用递归项大于 100% 的 inclusive 数值作为占比。
